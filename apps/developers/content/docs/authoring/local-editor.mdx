---
title: Edit Hosted Content Locally
description: Run the Studio on your machine with ffd editor, handle schema drift, and keep the token out of the browser.
---

`ffd editor` runs the same Studio that you mount in your application, on a loopback port of your machine. You get browse, search, edit, history, compare, restore, exact-locale publication, form layout, and Preview without a Studio registration.

## Prerequisites

Link the project configuration and make sure that the local Tier 1 schema is valid. Then sign in with the CLI. The editor needs the `studio:content` scope, so sign in again after an upgrade.

```bash
ffd login
ffd editor
```

The editor uses your user login, because the Studio shows each form for your project role. It does not accept a management token. If `FFD_MANAGEMENT_TOKEN` is set, the command fails with `CLI_EDITOR_OAUTH_REQUIRED`.

## Start the editor

1. The CLI validates the local schema before it reads any credential.
2. The CLI checks that you can open the Studio for the project and environment. If you are not a member, or the CMS is off, the command stops before it binds a port.
3. The CLI binds an ephemeral `127.0.0.1` port and opens `http://127.0.0.1:<port>/studio/session` with a one-time challenge in the URL fragment.
4. The page exchanges the challenge for an `HttpOnly` `SameSite=Strict` session cookie, then opens the Studio. The challenge works once.

Press Ctrl+C to stop the editor. A reload in the same browser keeps working while the editor runs.

## Handle schema drift

The CLI watches the configured Tier 1 output and compares it with the hosted schema every five seconds.

- If the local and hosted structure match, saving and publishing work.
- If they differ, the Studio shows a notice and pauses create, rename, save, restore, publish, and unpublish. Run `ffd schema plan`, review the changes, then run `ffd schema push` with exact acknowledgements.
- If the local source is invalid, the Studio shows the diagnostic code and pauses the same writes.

The Studio always shows the hosted form. Fields that exist only in local code appear after you push them.

## Preview

If the environment has a Preview URL, the Studio Preview panel works in the editor. See [Studio Preview](/docs/preview/studio-preview). If the Preview URL changes while the editor runs, restart the editor.

## Security boundary

The loopback server is a closed backend-for-frontend (a small server that calls the API for the browser), not a proxy. It accepts only the Studio route list and validates every request body and every API response. It rejects non-loopback peers, `Host` confusion, encoded paths, cross-site fetch metadata, mutations without the exact `Origin`, unknown routes, and oversized bodies.

The OAuth access and refresh tokens stay in Node memory and the OS credential store. They never enter browser HTML, JavaScript, URLs, storage, or headers that the browser chooses. Each response uses a locked Content Security Policy and `no-store`.

Do not expose the loopback port through a tunnel, container port mapping, or LAN bind.
