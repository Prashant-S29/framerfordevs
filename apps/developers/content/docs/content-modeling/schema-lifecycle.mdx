Schema publication is optimistic and versioned. Stable source identities and structural contracts are defined in Tier 1 TypeScript, while labels and editor layout remain hosted presentation authority. Dashboard collection creation and structure mutation are retired: direct legacy mutation calls return `410 DASHBOARD_SCHEMA_AUTHORING_RETIRED`. Local edits do not alter the current published schema or generated tooling until an exact server plan is applied.

## Change Classification

Before publication, the platform compares the draft with the current published revision. Typical outcomes include:

- Adding an optional field: additive
- Renaming a display label: metadata-only
- Adding a required field: potentially breaking
- Tightening validation: potentially breaking
- Renaming a published API key: breaking
- Removing a field or enum value: breaking
- Changing to an incompatible field kind: breaking

Risky publication requires exact acknowledgement of every and only the server-returned risky change ID. The server remains the validation and classification authority.

## Immutable Revision Authority

A successful publication creates a new immutable schema revision and updates the collection's current published head. Existing content publications retain the revision against which they were compiled.

## Generated Tooling

Tooling reconstructs and integrity-checks the complete published revision before projecting its public contract. A layout-, help-, or role-only change may advance revision metadata without changing generated type bytes.

Run `ffd schema plan` and `ffd schema push --acknowledge CHANGE_ID` to publish code-owned structure. Run `ffd schema check` in CI to detect stale generated output. Entry content changes never create schema drift.
