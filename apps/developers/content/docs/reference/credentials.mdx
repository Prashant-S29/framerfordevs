| Authority                                | Intended use                              | Browser-safe             |
| ---------------------------------------- | ----------------------------------------- | ------------------------ |
| Public Delivery                          | Explicitly public collection reads        | Yes, under Delivery CORS |
| Protected Delivery credential            | Server/deployment published-content reads | No                       |
| Preview credential                       | Trusted draft preview                     | No                       |
| Management credential with `schema.read` | Headless CI schema checks                 | No                       |
| OAuth device authority                   | Interactive official CLI                  | Native CLI only          |
| Webhook signing secret                   | Verify outbound events                    | No                       |

Credentials are named, scoped, revocable, environment-aware, and auditable. A credential family is accepted only by its intended boundary.

## Storage

Use deployment secret storage for Delivery, Preview, and CI credentials. The CLI persists rotating OAuth authority only through the native OS credential store and fails closed when secure storage is unavailable.

Never place credentials in project configuration, generated code, schema locks, URLs, logs, traces, analytics, examples, or documentation assets.

## Rotation and Revocation

API credential rotation is staged: start discloses an unusable pending successor once, activation begins a fixed overlap of no more than 24 hours, and completion retires the predecessor early. A pending rotation can be canceled without changing the active predecessor. Emergency revocation closes every usable or pending key in an open rotation atomically.

Webhook signing-secret rotation follows the same explicit pending, overlap, and retirement workflow. OAuth refresh authority rotates according to the authorization server and is removed by logout/revocation.

See [Operational administration and recovery](/docs/operational-recovery) for exact CLI workflows and ambiguous-response recovery.
