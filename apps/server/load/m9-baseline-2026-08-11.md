# M9 Delivery baseline — 2026-08-11

The final local/manual capacity baseline used one production server process, PostgreSQL and Redis on the same Docker host, PostgreSQL pool maximum 10, 10,000 current English publications, six query-enabled scalar fields plus one pinned reference projection, and approximately 4.8 KiB snapshots (4,794-byte current maximum).

Only the 60-second measured stage contributes to custom metrics; each full profile first completed a 15-second warm-up.

The hot-credential profile alternated cost-1 item reads and cost-6 list reads against one credential. Redis shared its quota across server processes on ports 3000 and 3002: the measured 429 ratio was 75%, with 690 primary-process and 660 secondary-process 429 responses. Every 429 carried the stable `RATE_LIMITED` envelope, credential quota limit, bounded remaining/reset values, and `Retry-After`.

The outage profile stopped Redis for 15 seconds during measured traffic. Delivery stayed available through bounded process-local fallback; the reconnect window produced a maximum measured latency of 420.06 ms. Redis restarted during continued traffic, became healthy, and recreated 41 bounded limiter keys, proving recovery.

The response-boundary profile temporarily made 32 current snapshots 147,902 canonical bytes each, causing the list preflight to reject over 4 MiB before serialization. The fixture utility restored every current snapshot to a maximum of 4,794 bytes. A second short repeat sampled server memory at 288.0 MiB initially, 288.2 MiB peak, and 282.3 MiB finally, showing no run-proportional growth.

## Final invariants

- 0 active/waiting application connections or open non-idle transactions
- 10,000 current fixture publications, current maximum 4,794 canonical bytes, and 0 duplicate unique claims
- 0 current oversized-boundary documents after restoration
- 41 bounded Redis keys with observed TTL range 30,370–88,030 ms after the final recovery checks
- PostgreSQL, Redis, server, and web healthy; temporary second server absent
- Capacity traffic had no unexpected degraded-memory decisions after normal Redis connectivity was verified

The wrapper at `apps/server/load/run-delivery-k6.sh` must be used instead of Docker `--env-file`: the ignored source file is shell-safe, while Docker preserves its quote characters as credential/value data.
