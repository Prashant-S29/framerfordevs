## Existing backlog rollout

The developer authorized draining 10,155 existing supported outbox rows. The first implementation projected 10,099 external events and one internal event before two valid recursive-schema publications blocked the last batch. Those schemas contained 146 and 180 changed stable nodes, exposing an incorrect 100-field event-contract assumption. The first serial per-row dispatcher also needed about 34.045 seconds for 10,099 canonical events, narrowly missing the 30-second target. The dispatcher was changed to bulk canonical insertion, one bounded event-time subscription-window query, bulk conflict-safe fan-out, and one processed-marker update per batch. Historical closed subscriptions are now correctly eligible when event occurrence falls inside their interval.

The remaining 55 events then projected successfully. Final backlog reconciliation reported:

The first live controlled-TLS run exposed two production-path issues not visible through the structural adapter tests. Healthy fan-out uses five independent endpoint hostnames and completed within target.
