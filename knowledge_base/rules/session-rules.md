# Session Preparation Rules

Before changing code, read completely:

1. `knowledge_base/product.md`
2. `knowledge_base/prd/cms.md`
3. Every rule linked by `knowledge_base/rules/index.md`
4. `knowledge_base/context.md`
5. `knowledge_base/progress.md`
6. The active milestone in `knowledge_base/milestone.md`
7. `knowledge_base/learnings.md`
8. Relevant decision records, source files, and installed skill files

At the beginning of every session:

- Inspect `git status` and the recent `git log` before reporting repository, milestone, approval, or commit state.
- Treat Git as the authority for whether work has been committed; reconcile stale status documents rather than repeating them uncritically.
- Recheck Git immediately before a milestone handoff or status summary when repository state may have changed.
- Do not implement from a stale chat summary when repository sources are available.
